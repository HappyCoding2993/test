# OpenSpec: Codex 功能测试仓需求定义

## 1. 背景与目标

目标是提供一个**可运行、可扩展、可验证**的最小代码仓，用于系统化测试 Codex 在以下场景的能力：

1. 从需求到代码实现
2. 代码修改与重构
3. 测试用例补齐与回归
4. CLI 交互与本地持久化

## 2. 角色与使用场景

- **主要用户**：需要评估 Codex 代码生成与改造能力的开发者。
- **典型场景**：
  - 给出新需求后，让 Codex 修改模型与测试。
  - 对 CLI 功能进行增强并验证回归。
  - 替换持久化方案（JSON -> SQLite）并保证兼容。

## 3. 功能需求（Must Have）

1. 提供任务实体（Task）与任务管理能力。
2. 支持新增、列出、完成、删除任务。
3. 支持本地持久化，默认使用 JSON 文件。
4. 提供命令行入口，能独立执行上述操作。
5. 提供自动化测试覆盖核心行为。
6. 提供清晰 README，包含运行与扩展说明。

## 4. 非功能需求

1. Python 版本兼容主流本地开发环境（3.10+）。
2. 无外部服务依赖，可离线运行。
3. 代码结构简单，便于 Codex 进行小步修改。

## 5. 验收标准

1. 在空目录初始化后，执行测试命令应通过。
2. 通过 CLI 可完整走通 add/list/done/delete 流程。
3. 数据可在进程重启后保持一致（持久化生效）。
4. README 中应给出下一步可扩展任务，便于持续测试 Codex。
